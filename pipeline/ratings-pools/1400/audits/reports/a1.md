## 518B: REJECTED

The required checks `algorithmicallyWrong` and `fullTests` cannot be signed off with the recorded counterexamples. `incorrectAnalysis.test` must equal the evidence `failedTest`, and for four of the five counted incorrect submissions that test does not demonstrate an algorithmic defect.

- **CRLF artifact.** The recorded `failedTest` is 0001 for 42384570, 46031625 and 46142003. Test 0001 is the official CRLF pair `AbC\r\nDCbA\r\n`, expected `3 0`.
  - All three read lines with `input()` and never strip it, so the trailing `\r` of `s` "matches" the `\r` in `t`, and they print `4 0`.
  - With the same input normalised to LF, all three print the correct `3 0`. On Codeforces, `\r` is not part of the line.
  - So the recorded counterexample is a line-ending artifact of the harness, not a valid input on which the algorithm is wrong.
  - With LF input they do fail elsewhere: 42384570 first fails on 0009, 46031625 on 0008, and 46142003 on 0009. The evidence names 0001 instead.
- **45901580, `failedTest` 0001.** The program prints debug lines (`print(x, S[x], T[x])`, `print(yay)`) before the answer. On 0001 its final line `3 0` is correct, so the WA there comes from stray output, not an algorithmic error. The source does contain a real defect, `S[x] -= T[x]` after `T` has already been reduced, which over-counts WHOOPS. But the recorded test does not exercise it in isolation.
- **45701865, `failedTest` 0005.** This one is a genuine counterexample. `t_map[i] -= s_map[i]` runs after `s_map[i]` has been zeroed, so counts are never consumed and WHOOPS is over-counted: `zzzZZZ`/`ZZZzzZ` gives `5 3` instead of `5 1`.

Everything else for 518B checked out: hashes, statement, input constraints, expected outputs, oracle, deterministic generation, coverage, and all five accepted sources AC.

**Remediation.**
1. Normalise CRLF before giving input to Python sources, or record LF-normalised failures.
2. Re-select or re-run so that each counted incorrect submission's `failedTest` is a real algorithmic counterexample.
3. Exclude or deprioritise sources whose only failure on the recorded test is debug output.

**Systemic note.** Every official pair in all seven packages is CRLF. For the six approved problems, LF and CRLF runs give identical failure sets and identical failed tests, so they are unaffected.
